# 04 - 开发工作流和最佳实践

本文档详细介绍 n8n 项目的开发工作流程、代码质量保证、测试策略和团队协作最佳实践。

---

## 1. 开发周期概览

### 1.1 标准开发流程

```mermaid
graph LR
    A[需求分析] --> B[环境设置]
    B --> C[创建分支]
    C --> D[编码开发]
    D --> E[本地测试]
    E --> F[代码检查]
    F --> G[提交代码]
    G --> H[创建PR]
    H --> I[代码评审]
    I --> J[CI/CD检查]
    J --> K[合并代码]
    K --> L[部署发布]
```

### 1.2 开发环境切换流程

```bash
# 1. 同步上游代码
git fetch upstream
git checkout master
git merge upstream/master

# 2. 创建功能分支
git checkout -b feature/new-feature-name

# 3. 启动开发环境
pnpm dev

# 4. 进行开发工作
# ... 编码、测试、调试

# 5. 提交变更
git add .
git commit -m "feat: add new feature description"

# 6. 推送分支
git push origin feature/new-feature-name

# 7. 创建 Pull Request
```

## 2. Git 工作流规范

### 2.1 分支管理策略

```bash

feature/feature-name     # 新功能开发
```

### 2.2 提交信息规范

遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范：

```bash
# 提交格式
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]

# 示例
feat(nodes): add Discord integration node
fix(core): resolve workflow execution timeout issue  
docs(api): update REST API documentation
test(editor): add unit tests for workflow canvas
refactor(cli): optimize server startup performance
chore(deps): update dependencies to latest versions
```

**提交类型说明:**
```
feat:     新功能
fix:      问题修复
docs:     文档变更
style:    代码格式调整
refactor: 代码重构
test:     测试相关
chore:    构建过程或辅助工具变更
perf:     性能优化
ci:       CI/CD 相关变更
```

### 2.3 代码合并策略

```bash

# 2. 解决冲突（如有）
git status
git add .
git rebase --continue

# 3. 强制推送（谨慎使用）
```

### 5.2 错误处理模式

```typescript
// 统一错误处理策略
import { ApplicationError } from 'n8n-workflow';

class WorkflowService {
  async executeWorkflow(workflowId: string): Promise<IExecutionResponse> {
    try {
      // 参数验证
      if (!workflowId) {
        throw new ApplicationError('Workflow ID is required');
      }
      
      // 业务逻辑
      const workflow = await this.getWorkflow(workflowId);
      if (!workflow) {
        throw new ApplicationError(`Workflow ${workflowId} not found`);
      }
      
      return await this.runWorkflow(workflow);
      
    } catch (error) {
      // 错误日志记录
      this.logger.error('Workflow execution failed', {
        workflowId,
        error: error.message,
        stack: error.stack
      });
      
      // 重新抛出业务错误
      if (error instanceof ApplicationError) {
        throw error;
      }
      
      // 包装未知错误
      throw new ApplicationError(
        'Internal server error during workflow execution',
        { cause: error }
      );
    }
  }
}
```

### 5.3 异步代码模式

```typescript
// ✅ 使用 async/await
async function processItems(items: INodeExecutionData[]): Promise<INodeExecutionData[]> {
  const results: INodeExecutionData[] = [];
  
  for (const item of items) {
    try {
      const processed = await processItem(item);
      results.push(processed);
    } catch (error) {
      // 处理单个项目错误，不影响其他项目
      this.logger.warn('Failed to process item', { error, item });
    }
  }
  
  return results;
}

// ✅ 并行处理（当顺序不重要时）
async function processItemsInParallel(items: INodeExecutionData[]): Promise<INodeExecutionData[]> {
  const promises = items.map(async (item) => {
    try {
      return await processItem(item);
    } catch (error) {
      this.logger.warn('Failed to process item', { error, item });
      return null; // 或者返回错误标记
    }
  });
  
  const results = await Promise.all(promises);
  return results.filter(result => result !== null);
}

// ❌ 避免的模式
function badAsyncPattern(callback: Function) {
  // 不要混用 callback 和 Promise
  processData()
    .then(result => callback(null, result))
    .catch(error => callback(error));
}
```

### 5.4 性能优化原则

```typescript
// 内存管理
class MemoryEfficientProcessor {
  private cache = new Map<string, any>();
  private maxCacheSize = 1000;
  
  async processLargeDataset(data: any[]): Promise<any[]> {
    // 分批处理大数据集
    const batchSize = 100;
    const results: any[] = [];
    
    for (let i = 0; i < data.length; i += batchSize) {
      const batch = data.slice(i, i + batchSize);
      const batchResults = await this.processBatch(batch);
      results.push(...batchResults);
      
      // 定期清理内存
      if (i % 1000 === 0) {
        this.cleanupCache();
      }
    }
    
    return results;
  }
  
  private cleanupCache(): void {
    if (this.cache.size > this.maxCacheSize) {
      // 清理最旧的缓存条目
      const entries = Array.from(this.cache.entries());
      const toDelete = entries.slice(0, entries.length - this.maxCacheSize);
      toDelete.forEach(([key]) => this.cache.delete(key));
    }
  }
}

// 数据库查询优化
class OptimizedRepository {
  async findWorkflowsWithExecutions(limit: number = 20): Promise<IWorkflow[]> {
    // 使用适当的查询优化
    return await this.repository
      .createQueryBuilder('workflow')
      .leftJoinAndSelect('workflow.executions', 'execution')
      .where('workflow.active = :active', { active: true })
      .orderBy('workflow.updatedAt', 'DESC')
      .limit(limit)
      .getMany();
  }
  
  // 避免 N+1 查询问题
  async findWorkflowsWithNodes(workflowIds: string[]): Promise<IWorkflow[]> {
    return await this.repository
      .createQueryBuilder('workflow')
      .leftJoinAndSelect('workflow.nodes', 'node')
      .whereInIds(workflowIds)
      .getMany();
  }
}
```

```typescript
describe('Workflow Execution Performance', () => {

  });
```

```typescript
class MemoryMonitor {

      this.instance = new MemoryMonitor();

    return this.instance;
  }
  
  logMemoryUsage(label: string): void {

      heapTotal: `${Math.round(usage.heapTotal / 1024 / 1024)} MB`,
      heapUsed: `${Math.round(usage.heapUsed / 1024 / 1024)} MB`,
      external: `${Math.round(usage.external / 1024 / 1024)} MB`,
      timestamp: new Date().toISOString()
    });
  }
```
