## 3. 后端调试

### 3.1 方法一：从 VSCode 启动调试

这是最常用的调试方法，可以完全控制启动过程。

#### 启动 n8n 调试模式

```bash
# 1. 在 VSCode 中打开项目
code /path/to/n8n

# 2. 打开 "Run and Debug" 面板 (Ctrl+Shift+D)
# 3. 选择 "Launch n8n with debug" 配置
# 4. 点击绿色播放按钮启动调试
```

**调试配置详解:**
```json
{
  "name": "Launch n8n with debug",
  "program": "${workspaceFolder}/packages/cli/bin/n8n",  // n8n 可执行文件
  "cwd": "${workspaceFolder}/packages/cli/bin",           // 工作目录
  "request": "launch",                                    // 启动新进程
  "skipFiles": ["<node_internals>/**"],                  // 跳过 Node.js 内部文件
  "type": "node",                                         // Node.js 调试器
  "env": {
    // "N8N_PORT": "5679"                               // 可选：自定义端口
  }
}
```

#### 开发模式调试

```bash
# 使用 buildAndDev 配置进行开发调试
# 1. 选择 "Launch n8n CLI dev with debug" 配置
# 2. 这将启动开发模式并等待调试器连接
```

**开发调试配置详解:**
```json
{
  "name": "Launch n8n CLI dev with debug",
  "runtimeExecutable": "pnpm",                    // 使用 pnpm
  "cwd": "${workspaceFolder}/packages/cli",       // CLI 包目录
  "runtimeArgs": ["run", "buildAndDev", "--", "--inspect-brk"], // 启动参数
  "console": "integratedTerminal",                 // 集成终端输出
  "restart": true,                                 // 支持自动重启
  "autoAttachChildProcesses": true,                // 自动附加子进程
  "envFile": "${workspaceFolder}/.env"             // 加载环境变量文件
}
```

### 3.2 方法二：附加到运行中的进程

适用于已经启动的 n8n 进程的调试。

```bash
# 1. 启动 n8n (在调试模式下)
node --inspect packages/cli/bin/n8n

# 或者启动开发模式
node --inspect packages/cli/dist/index.js

# 2. 在 VSCode 中选择 "Attach to running n8n"
# 3. 从进程列表中选择对应的 Node.js 进程
```

**附加调试的优点:**
- 不会重启应用程序
- 保持当前状态和数据
- 可以在运行时动态调试

## 7. 调试最佳实践

### 7.1 断点设置技巧

```typescript
// ✅ 好的断点设置
function processWorkflow(workflow: IWorkflowBase) {
  // 在函数入口设置断点，检查输入参数
  debugger;
  
  if (!workflow || !workflow.nodes) {
    // 在错误条件处设置断点
    debugger;
    throw new Error('Invalid workflow');
  }
  
  const result = executeNodes(workflow.nodes);
  
  // 在返回前设置断点，检查返回值
  debugger;
  return result;
}

// ❌ 避免的断点设置
function badExample() {
  for (let i = 0; i < 1000; i++) {

    console.log(i);
  }
```

```typescript
// 在 VSCode 中右键断点 -> "Edit Breakpoint" -> "Conditional Breakpoint"

// 示例条件断点
function processItems(items: INodeExecutionData[]) {
  // 条件: items.length > 10
  // 只有当 items 数量大于 10 时才暂停
  debugger;
  
  for (const item of items) {
    // 条件: item.json.error !== undefined
    // 只有当存在错误时才暂停

  }
}
```

### 7.3 日志调试

```typescript
// 使用结构化日志进行调试
import { Logger } from '@n8n/logger';

const logger = Logger.getInstance();

class WorkflowService {
  async executeWorkflow(workflowId: string) {
    logger.debug('Starting workflow execution', {
      workflowId,
      timestamp: new Date().toISOString(),
      context: 'WorkflowService.executeWorkflow'
    });
    
    try {
      const result = await this.runWorkflow(workflowId);
      
      logger.debug('Workflow execution completed', {
        workflowId,
        resultCount: result.length,
        duration: Date.now() - startTime
      });
      
      return result;
    } catch (error) {
      logger.error('Workflow execution failed', {
        workflowId,
        error: error.message,
        stack: error.stack
      });
      throw error;
    }
  }
}
```

```typescript
  async executeWithTiming(operation: string, fn: () => Promise<any>) {
    console.time(`${operation}_duration`);
    console.timeLog(`${operation}_duration`, 'Starting operation');
    
    try {
      const result = await fn();
      console.timeLog(`${operation}_duration`, 'Operation completed');
```

## 10. 常见调试问题

### 10.1 断点不生效

```bash
# 问题: 断点被跳过或不暂停
# 原因: 源码映射问题或文件路径不匹配

# 解决方案:
# 1. 确保启用了源码映射
"sourceMaps": true

# 2. 检查输出文件路径
"outFiles": ["${workspaceFolder}/packages/*/dist/**/*.js"]

# 3. 重新构建项目
pnpm build
```

### 10.2 调试器连接失败

```bash
# 问题: 无法连接到调试端口
# 原因: 端口被占用或防火墙阻挡

# 解决方案:
# 1. 检查端口占用
lsof -i :9229

# 2. 使用不同的调试端口
node --inspect=0.0.0.0:9230 packages/cli/bin/n8n

# 3. 检查防火墙设置
sudo ufw allow 9229
```

### 10.3 前端调试源码映射问题

```bash
# 问题: 前端代码调试时跳转到编译后的代码
# 原因: Vite 源码映射配置问题

# 解决方案:
# 1. 确保 Vite 开发模式启用了源码映射
# 2. 清理缓存重新启动
rm -rf packages/editor-ui/dist
rm -rf packages/editor-ui/node_modules/.vite
pnpm dev:fe
```

### 10.4 TypeScript 调试问题

```bash
# 问题: TypeScript 代码断点不准确
# 原因: ts-node 或编译配置问题

# 解决方案:
# 1. 使用编译后的 JavaScript 进行调试
pnpm build
node --inspect packages/cli/dist/index.js

# 2. 配置 TypeScript 调试
{
  "type": "node",
  "runtimeArgs": ["-r", "ts-node/register"],
  "args": ["${file}"]
}
```
