# 02 - 开发服务器启动指南

本文档详细介绍 n8n 的各种开发模式启动方法，包括全量开发、选择性开发、热重载配置和性能优化建议。

---

## 1. 开发模式概览

### 1.1 可用的开发命令

n8n 提供了多种开发模式以适应不同的开发需求：

```bash
# 全量开发模式
pnpm dev           # 启动除 design-system, chat, task-runner 外的所有包

# 选择性开发模式  
pnpm dev:be        # 仅后端开发（排除前端包）
pnpm dev:fe        # 仅前端开发（后端服务器 + 前端开发服务器）
pnpm dev:ai        # AI/LangChain 节点开发

# 单独启动模式
pnpm start         # 生产模式启动（需要先 build）
pnpm start:tunnel  # 启动并开启 localtunnel

# 特殊服务模式
pnpm worker        # 仅启动 worker 进程
pnpm webhook       # 仅启动 webhook 服务
```

### 1.2 开发模式对比

| 模式 | 包含组件 | 适用场景 | 资源消耗 |
|------|----------|----------|----------|
| `pnpm dev` | 后端 + 前端 (除部分) | 全栈开发 | 高 |
| `pnpm dev:be` | 仅后端组件 | 后端 API 开发 | 中 |
| `pnpm dev:fe` | 后端服务 + 前端开发 | 前端 UI 开发 | 中 |
| `pnpm dev:ai` | AI 相关包 | AI 节点开发 | 低 |

## 2. 全量开发模式

### 2.1 标准开发模式

```bash
# 启动全量开发模式
pnpm dev

# 等价的 turbo 命令
turbo run dev --parallel --env-mode=loose --filter=!@n8n/design-system --filter=!@n8n/chat --filter=!@n8n/task-runner
```

**启动的服务:**
- ✅ CLI 服务器 (端口 5678)
- ✅ 前端编辑器 (Vite 开发服务器)
- ✅ 核心工作流引擎
- ✅ 节点基础包
- ✅ 所有工作区包
- ❌ 设计系统 (已排除)
- ❌ Chat 包 (已排除)
- ❌ Task Runner (已排除)

## 3. 选择性开发模式

### 3.1 后端开发模式

适用于专注后端 API、工作流引擎、节点开发的场景。

```bash
# 启动后端开发模式
pnpm dev:be

# 等价命令
turbo run dev --parallel --env-mode=loose --filter=!@n8n/design-system --filter=!@n8n/chat --filter=!@n8n/task-runner --filter=!n8n-editor-ui
```

**包含的服务:**
- ✅ CLI 服务器
- ✅ 核心工作流引擎  
- ✅ 节点基础包
- ✅ 所有后端工作区包
- ❌ 前端编辑器 UI
- ❌ 设计系统
- ❌ Chat 包

**使用场景:**
- 开发新的节点类型
- 修改工作流执行逻辑
- 调试 API 端点
- 性能分析和优化

### 3.2 前端开发模式

适用于专注前端 UI、编辑器、组件开发的场景。

```bash
# 启动前端开发模式
pnpm dev:fe

# 实际执行的命令组合
run-p start "dev:fe:editor --filter=@n8n/design-system"
```

**启动的服务:**
- ✅ 后端服务器 (生产模式)
- ✅ 前端编辑器 (开发模式)
- ✅ 设计系统 (开发模式)
- ✅ Vite HMR 热重载

**使用场景:**
- 开发编辑器界面
- 调试前端组件
- 样式和布局调整
- 用户交互优化

### 3.3 AI 节点开发模式

专门为 AI/LangChain 节点开发优化的模式。

```bash
# 启动 AI 开发模式
pnpm dev:ai

# 等价命令
turbo run dev --parallel --env-mode=loose --filter=@n8n/n8n-nodes-langchain --filter=n8n --filter=n8n-core
```

**包含的服务:**
- ✅ CLI 服务器
- ✅ 核心工作流引擎
- ✅ LangChain 节点包
- ❌ 其他非必需包

**使用场景:**
- 开发 AI 节点
- 调试 LangChain 集成
- 测试 AI 工作流

## 4. 热重载配置

### 4.1 启用热重载

热重载功能可以在代码更改时自动重新加载，无需手动重启服务器。

```bash
# 启用热重载的开发模式
N8N_DEV_RELOAD=true pnpm dev

# 或者设置环境变量后启动
export N8N_DEV_RELOAD=true
pnpm dev
```

### 4.2 热重载工作原理

```typescript
// 热重载机制
const hotReload = {
  fileWatcher: 'chokidar',        // 文件监控
  triggerPaths: [
    'packages/nodes-base/dist/',   // 节点包
    'packages/core/dist/',         // 核心包
    'packages/cli/dist/',          // CLI 包
    // ... 其他包
  ],
  reloadStrategy: 'incremental',   // 增量重载
  excludePatterns: [
    '**/*.test.js',               // 测试文件
    '**/node_modules/**',         // 依赖包
    '**/.git/**'                  // Git 文件
  ]
};
```

### 4.3 热重载性能考虑

```bash
# 性能影响评估
File Watching: 200-500MB 额外内存占用
CPU Usage:     5-15% 持续 CPU 使用
I/O Impact:    频繁磁盘读写操作

# 针对低性能机器的优化
NO_FILE_WATCH=true pnpm dev    # 禁用文件监控
```

**热重载最佳实践:**
- 在 SSD 上运行项目以减少 I/O 延迟
- 关闭不必要的应用程序释放内存
- 使用选择性开发模式减少监控的文件数量
- 在虚拟机中开发时考虑禁用热重载

## 5. 数据库配置开发

n8n 支持多种数据库，可以在开发时选择不同的数据库后端。

### 5.1 SQLite (默认)

```bash
# 使用 SQLite 数据库 (默认)
pnpm dev

# 显式指定 SQLite
DB_TYPE=sqlite pnpm dev

# SQLite 数据文件位置
~/.n8n/database.sqlite
```

### 5.2 PostgreSQL

```bash
# 使用 PostgreSQL
DB_TYPE=postgresdb \
DB_POSTGRESDB_HOST=localhost \
DB_POSTGRESDB_PORT=5432 \
DB_POSTGRESDB_DATABASE=n8n \
DB_POSTGRESDB_USER=n8n \
DB_POSTGRESDB_PASSWORD=n8n \
pnpm dev
```

### 5.3 MySQL/MariaDB

```bash
# 使用 MySQL
DB_TYPE=mysqldb \
DB_MYSQLDB_HOST=localhost \
DB_MYSQLDB_PORT=3306 \
DB_MYSQLDB_DATABASE=n8n \
DB_MYSQLDB_USER=n8n \
DB_MYSQLDB_PASSWORD=n8n \
pnpm dev

# 使用 MariaDB
DB_TYPE=mariadb \
DB_MARIADB_HOST=localhost \
DB_MARIADB_PORT=3306 \
DB_MARIADB_DATABASE=n8n \
DB_MARIADB_USER=n8n \
DB_MARIADB_PASSWORD=n8n \
pnpm dev
```

### 5.4 Docker 数据库快速启动

```bash
# PostgreSQL
docker run -d \
  --name n8n-postgres \
  -e POSTGRES_DB=n8n \
  -e POSTGRES_USER=n8n \
  -e POSTGRES_PASSWORD=n8n \
  -p 5432:5432 \
  postgres:15

# MySQL
docker run -d \
  --name n8n-mysql \
  -e MYSQL_DATABASE=n8n \
  -e MYSQL_USER=n8n \
  -e MYSQL_PASSWORD=n8n \
  -e MYSQL_ROOT_PASSWORD=root \
  -p 3306:3306 \
  mysql:8.0
```

## 6. 高级开发配置

### 6.1 环境变量配置

创建 `.env` 文件进行个性化配置：

```bash
# .env 文件示例
N8N_PORT=5678
N8N_HOST=0.0.0.0

# 数据库配置
DB_TYPE=sqlite

# 日志配置
N8N_LOG_LEVEL=debug
N8N_LOG_OUTPUT=console

# 开发配置
N8N_DEV_RELOAD=true
N8N_DISABLE_UI=false

# 安全配置 (开发环境)
N8N_DISABLE_PRODUCTION_MAIN_PROCESS=true
N8N_CREDENTIALS_OVERWRITE_ENDPOINT=file

# 性能配置
N8N_WORKER_MAX_CONCURRENT_JOBS=2
```

### 6.2 自定义端口配置

```bash
# 修改默认端口
N8N_PORT=8080 pnpm dev

# 或者在 .env 文件中设置
echo "N8N_PORT=8080" >> .env
pnpm dev
```

### 6.3 多实例开发

```bash
# 终端 1: 主实例
N8N_PORT=5678 pnpm dev

# 终端 2: 测试实例  
N8N_PORT=5679 \
N8N_USER_FOLDER=~/.n8n-test \
pnpm dev

# 终端 3: Worker 实例
N8N_PORT=5680 \
pnpm worker
```

## 7. 手动分包开发

对于需要精确控制的开发场景，可以手动启动特定包。

### 7.1 手动后端开发

```bash
# 终端 1: 构建并监控核心包
cd packages/core
pnpm watch

# 终端 2: 构建并监控节点包
cd packages/nodes-base  
pnpm watch

# 终端 3: 启动 CLI 并启用热重载
cd packages/cli
N8N_DEV_RELOAD=true pnpm dev
```

### 7.2 手动前端开发

```bash
# 终端 1: 启动后端服务器
pnpm start

# 终端 2: 启动前端开发服务器
cd packages/editor-ui
pnpm dev

# 前端将在 http://localhost:5173 提供服务
# 并自动代理 API 请求到后端
```

### 7.3 单独节点包开发

```bash
# 开发自定义节点包
cd packages/nodes-base  # 或你的自定义节点包
pnpm watch

# 在另一个终端启动 CLI
cd packages/cli
N8N_DEV_RELOAD=true pnpm dev
```

## 9. 常见启动问题

### 9.1 端口冲突

```bash
# 问题: 端口 5678 已被占用
# 解决: 杀死占用进程或更换端口

# 查找占用进程
lsof -i :5678

# 杀死进程
kill -9 <PID>

# 或更换端口
N8N_PORT=8080 pnpm dev
```

### 9.2 内存不足

```bash
# 问题: 内存不足导致启动失败
# 解决: 使用选择性开发模式

# 仅启动后端
pnpm dev:be

# 或调整 Node.js 内存限制
NODE_OPTIONS="--max-old-space-size=4096" pnpm dev
```

### 9.3 构建失败

```bash
# 问题: TypeScript 编译错误
# 解决: 清理并重新构建

pnpm clean
pnpm build
pnpm dev
```

### 9.4 热重载不工作

```bash
# 问题: 代码更改后没有自动重载
# 解决: 检查文件权限和路径

# 确保启用了热重载
N8N_DEV_RELOAD=true pnpm dev

# 检查文件权限
ls -la packages/*/dist/

# 手动重启开发服务器
```

## 10. 性能优化建议

### 10.1 硬件优化

```bash
# SSD 存储: 减少 I/O 延迟
# 16GB+ RAM: 避免内存交换
# 多核 CPU: 并行构建和编译
```

### 10.2 软件优化

```bash
# 关闭不必要的 IDE 插件
# 使用选择性开发模式
# 定期清理 node_modules

pnpm store prune
pnpm cache delete
```

### 10.3 网络优化

```bash
# 使用国内镜像 (中国用户)
pnpm config set registry https://registry.npmmirror.com/

# 使用本地缓存
pnpm config set store-dir ~/.pnpm-store
```

## 11. 开发模式对比总结

| 特性 | `pnpm dev` | `pnpm dev:be` | `pnpm dev:fe` | `pnpm dev:ai` |
|------|------------|---------------|---------------|---------------|
| 启动时间 | 长 (2-5分钟) | 中 (1-3分钟) | 中 (1-3分钟) | 短 (30秒-1分钟) |
| 内存使用 | 高 (2-4GB) | 中 (1-2GB) | 中 (1-2GB) | 低 (500MB-1GB) |
| CPU 使用 | 高 | 中 | 中 | 低 |
| 热重载 | 全支持 | 后端支持 | 前端支持 | 有限支持 |
| 适用场景 | 全栈开发 | 后端专项 | 前端专项 | AI 节点开发 |

选择合适的开发模式可以显著提升开发效率和系统性能。建议根据具体的开发任务选择最合适的模式。
